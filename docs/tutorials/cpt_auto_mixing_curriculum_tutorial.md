# CPT 数据自动配比与课程学习

> 从 278 个异构数据集到 L0–L5 分桶、逐 token 调度与可执行 Schedule

**方向：** CPT Data Engineering · Curriculum Learning · Multimodal Training  
**案例：** Qwen3.5-2B-Base CPT  
**训练规模：** 30B tokens  
**数据版本：** v2d15  
**作者：** 鞠少波

---

## §0 TL;DR：这套脚本真正自动化了什么

| 指标 | 数值 | 含义 |
|---|---:|---|
| 数据源 | 278 | 一一校验名称、路径和权重 |
| 难度与模态桶 | 6 | L0–L5 |
| 主课程阶段 | 5 | 按累计 token 切换 |
| 消融变体 | 4 | 可通过配置直接切换 |

> **一句话结论：** 系统不是手工填写 278 个数据集在每个阶段的权重，而是只维护**数据集基准权重、固定分桶、阶段 bucket 目标占比**三层信息，再自动展开为训练框架可消费的 278 维权重 schedule。

核心设计是“**桶间重配、桶内保形**”。课程只改变 L0–L5 六个桶在训练中的宏观份额；同一桶内数据集的相对权重沿用 v2d15 基线。这样既能控制课程方向，又避免为每个阶段手调 278 个数字。

## §1 为什么 CPT 数据配比不能靠手工

多模态 CPT 的数据源同时覆盖纯文本、图像问答、文档 OCR、多图、视频、内部业务数据和复杂推理。不同源的样本长度、视觉帧数、质量、难度与领域价值差异很大。只用静态混合会带来三个问题：训练早期被长视频和硬推理扰动；训练后期仍被大量简单开放数据稀释；每次改总 token 数或做消融都要重算大量权重。

完整处理链路为：

```text
数据画像                  固定分桶              阶段目标
模态、来源、任务、平均 token → L0–L5 难度阶梯 → 每阶段 6 个占比
                                                   ↓
训练调度                  自动展开
按 token 平滑变化        ← 生成 278 维权重
```

脚本把配置入口收敛为 `TRAIN_SIZE`、`CURRICULUM_LEVEL` 和 `CURRICULUM_VARIANT`。实验名、输出目录与 W&B 名称也从同一组参数自动派生，降低“训练配置正确、实验记录却串了”的风险。

## §2 L0–L5：把 278 维问题压缩成 6 维控制面

分桶来自 v2d15 的类型、数据类型、任务类型与平均 token 等画像列，随后固化为 `BUCKET_BY_NAME`。固定映射很重要：同一实验矩阵中，课程变体只能改变配比，不能悄悄改变数据定义。

| Bucket | 定位 | 数据源数 | 基线权重和 | 基线占比 | 主要内容 |
|---|---|---:|---:|---:|---|
| L0 | 文本预热 | 15 | 583.116210 | 15.96% | 开源纯文本、语料与通用 QA；短 token、低成本，用于建立语言与指令基础 |
| L1 | 短多模态主干 | 193 | 1698.132230 | 46.49% | 开源短图像、多模态 QA 与 caption；数量最多，是稳定训练的主体 |
| L2 | 结构化长多模态 | 18 | 118.549420 | 3.25% | 多图、文档、OCR、网页与高 token 结构化任务，逐步提升上下文复杂度 |
| L3 | 开源视频 | 7 | 293.400000 | 8.03% | 视频 caption 与 QA，引入更多帧和更长上下文，但仍保持开源分布 |
| L4 | 内部中难度 | 9 | 305.500000 | 8.36% | 内部图像/文本结构化 QA、OCR 等闭源数据，承担域适配过渡 |
| L5 | 内部硬尾 | 36 | 654.100000 | 17.91% | 内部视频、长上下文、grounding、world knowledge 与复杂推理，训练后段强化 |

> **分桶原则：** “难度”不是单一标签，而是来源、模态、序列成本、结构复杂度和任务推理强度的联合工程判断。脚本只保存最终分桶，不保存原始画像列，因此版本升级时应在外部保留可审计的分桶生成表。

## §3 核心算法：桶间重配，桶内相对权重不变

记数据集 $i$ 的基准权重为 $b_i$，所属桶为 $g(i)$，全体基准权重和为 $T$，桶 $g$ 的基准权重和为 $B_g$，某阶段对该桶的目标占比为 $q_g$。自动生成的新权重为：

$$
\boxed{w_i=b_i\times q_{g(i)}\times\frac{T}{B_{g(i)}}}
$$

脚本中的总基准权重为：

$$
T=3652.79786
$$

若 $q_g=0$，则该桶全部数据集权重置为 0。

这个公式同时满足两条不变量。第一，桶内任意两个数据集的新权重比仍等于基准权重比：

$$
\frac{w_i}{w_j}=\frac{b_i}{b_j},\qquad g(i)=g(j)
$$

第二，每个桶的新权重和精确等于 $q_gT$，所以六个桶的总权重仍为 $T$：

$$
\sum_{i:g(i)=g}w_i=q_gT,\qquad \sum_g q_g=1
$$

对应的核心代码为：

```python
def weights_for_targets(targets):
    base_sums = bucket_sums(BASE_WEIGHTS)
    result = []
    for name, base_weight in zip(NAMES, BASE_WEIGHTS):
        bucket = BUCKET_BY_NAME[name]
        target_share = targets[bucket]
        if target_share <= 0:
            result.append(0.0)
        else:
            scale = target_share * TARGET_WEIGHT_SUM / base_sums[bucket]
            result.append(base_weight * scale)
    return result
```

> **为什么这比手工权重更稳：** 新增阶段只需要写 6 个目标占比；替换训练规模只需要改总 token；基准表升级只需要替换基准权重与分桶映射。课程逻辑与数据集细节被解耦，变更面从“278 × 阶段数”缩小到“6 × 阶段数”。

## §4 `curriculum_full`：30B token 的五阶段课程

第一阶段使用常量权重；第二阶段开始，每个区间从上一阶段目标线性变化到当前阶段目标。边界以累计 token 而不是 step 定义，因此 global batch、动态 batch 或样本长度变化时，课程仍与实际训练量对齐。

### S1 开放短数据预热

**区间：** 0–3B tokens  
**训练进度：** 0–10%  
**内部数据占比：** 0%

| L0 | L1 | L2 | L3 | L4 | L5 |
|---:|---:|---:|---:|---:|---:|
| 24% | 62% | 6% | 8% | 0% | 0% |

完全屏蔽 L4/L5，先用 L0/L1 建立稳定基础；少量 L2/L3 让模型提前接触结构化和视频形态。

### S2 开放结构能力建设

**区间：** 3–10.5B tokens  
**训练进度：** 10–35%  
**内部数据占比：** 8%

| L0 | L1 | L2 | L3 | L4 | L5 |
|---:|---:|---:|---:|---:|---:|
| 20% | 55% | 7% | 10% | 5% | 3% |

开始少量引入内部数据，但主干仍由开放短多模态数据支撑。

### S3 视频与内部域引入

**区间：** 10.5–19.5B tokens  
**训练进度：** 35–65%  
**内部数据占比：** 17%

| L0 | L1 | L2 | L3 | L4 | L5 |
|---:|---:|---:|---:|---:|---:|
| 16% | 47% | 8% | 12% | 8% | 9% |

这是最长的 9B 区间，开放主干与内部域适配进入相对均衡的过渡期。

### S4 长上下文适配

**区间：** 19.5–25.5B tokens  
**训练进度：** 65–85%  
**内部数据占比：** 29%

| L0 | L1 | L2 | L3 | L4 | L5 |
|---:|---:|---:|---:|---:|---:|
| 12% | 38% | 8% | 13% | 12% | 17% |

L3–L5 合计达到 42%，强化视频、长上下文与闭源任务适配。

### S5 内部硬尾强化

**区间：** 25.5–30B tokens  
**训练进度：** 85–100%  
**内部数据占比：** 38%

| L0 | L1 | L2 | L3 | L4 | L5 |
|---:|---:|---:|---:|---:|---:|
| 10% | 32% | 8% | 12% | 15% | 23% |

最终混合保留 50% 的 L0/L1 稳定底座，同时把 L4/L5 提升到 38%，完成内部域与复杂能力收口。

### 任意训练规模的边界换算

设总训练规模为 $N$ B tokens，各阶段边界和长度为：

| 阶段 | Token 区间 | 区间长度 |
|---|---|---:|
| S1 | $0\rightarrow0.10N$ | $0.10N$ |
| S2 | $0.10N\rightarrow0.35N$ | $0.25N$ |
| S3 | $0.35N\rightarrow0.65N$ | $0.30N$ |
| S4 | $0.65N\rightarrow0.85N$ | $0.20N$ |
| S5 | $0.85N\rightarrow N$ | $0.15N$ |

HTML 版本提供可交互的训练规模换算器；Markdown 版本使用上表中的通用公式。

## §5 四组预设：把经验判断变成可证伪实验

| 变体 | 控制变量 | 要回答的问题 | 终态 L0/L1/L2/L3/L4/L5 |
|---|---|---|---|
| `fixed_v2d15` | 沿用原始 v2d15 桶占比 | 自动课程是否优于历史静态基线？ | 15.96/46.49/3.25/8.03/8.36/17.91% |
| `curriculum_full` | 先开放、后内部，五阶段渐变 | 完整课程是否同时改善稳定性和最终域能力？ | 10/32/8/12/15/23% |
| `no_curriculum_final_mix` | 从第一个 token 起固定使用终态 | 收益来自最终配比，还是来自课程顺序？ | 10/32/8/12/15/23% |
| `earlier_closed` | S1 即引入 10% L4/L5，之后更快增加 | 闭源域数据是否应该更早进入？ | 10/32/8/12/15/23% |
| `lower_closed_final` | 内部数据增长更慢，终态仅 28% | 38% 内部数据是否过强、是否损害通用能力？ | 14/42/8/8/12/16% |

最关键的一对是 `curriculum_full` 与 `no_curriculum_final_mix`：两者终态完全一致，差别只有“是否逐步引入”，因此最适合隔离课程学习本身的贡献。

## §6 从 Bash 到训练框架：配置如何闭环

### 6.1 单一 CONFIG 区域

```bash
TRAIN_SIZE=${TRAIN_SIZE:-30000000000}
CURRICULUM_LEVEL="${CURRICULUM_LEVEL:-token}"
CURRICULUM_VARIANT="${CURRICULUM_VARIANT:-curriculum_full}"
RUN_NAME="${MODEL_TAG}_${LR_TAG}_${DATA_VERSION}_${EXP_TAG}_${CURRICULUM_VARIANT}_${TRAIN_SIZE_TAG}_${BACKEND_TAG}"
```

`TOTAL_TOKENS` 与变体通过环境变量传给内嵌 Python。Python 负责校验和计算，输出 `data_config.yaml`；Bash 再生成 `training_config.yaml` 并把前者作为 `train_path` 接入流式多源数据集。

### 6.2 Schedule 语义

```yaml
level: token
boundary_type: token
schedule:
  - init_token: 0
    end_token: 3000000000
    schedule_type: const
    weights: [278 个 S1 权重]
  - init_token: 3000000000
    end_token: 10500000000
    schedule_type: changing
    init_weights: [278 个 S1 权重]
    end_weights: [278 个 S2 权重]
```

`changing` 表示区间内从上一目标向下一目标连续变化，而不是边界处突然跳变。脚本设置 `level: token`，并明确记录 WeightedMultiSourceDataset 会根据运行时平均 token 长度重加权采样；因此应同时观测“配置权重”和“实际消费 token 占比”。

### 6.3 训练侧配套

案例使用 32K 最大序列、128 帧、global batch 128、micro batch 1、FSDP2 full shard、动态 batch buffer 和 DCP 自动续训。数据调度与模型训练参数分层生成，避免为了改数据课程误改后端或并行配置。

## §7 自动配比必须自带的质量门禁

| 门禁 | 脚本已有检查 | 避免的问题 |
|---|---|---|
| 长度一致 | `SOURCES`、`NAMES`、`BASE_WEIGHTS` 均为 278 | 路径、名称与权重错位 |
| 唯一性 | source 和 name 分别无重复 | 同一数据被隐式加倍 |
| 分桶完整 | 每个 name 必须存在 bucket | 新增数据漏配导致静默丢失 |
| 占比守恒 | 每阶段六桶 targets 之和为 1 | 配比漂移或总量不守恒 |
| 零桶安全 | 目标为 0 时权重置零；目标非零但基线和为零则报错 | 除零或空桶伪配比 |
| 实验隔离 | RUN_NAME 必须带 backend，目录与 W&B 同名 | NPU/GPU 结果覆盖、记录串线 |

> **建议补充的运行时观测：** 每个阶段记录实际 token、样本数、图像数、帧数和平均序列长度的 bucket/source 分布；比较目标占比与实耗占比；同时按阶段监控 loss、梯度范数、吞吐、OOM/坏样本率和通用/内部评测。只有这样才能判断偏差来自 sampler、长度重加权、数据质量还是课程设计。

## §8 边界、风险与下一版改进

### 8.1 当前方案的边界

- **分桶是离线固定规则**：不会根据训练 loss 或能力掌握度自适应调整，因此属于预设课程，不是在线 curriculum。
- **桶内只保留历史相对权重**：若某个源质量显著变化，宏观 bucket 调度无法自动发现。
- **配置权重不等于实际 token 占比**：token-level sampler、动态 batch、长视频与坏样本过滤都可能造成偏差。
- **阶段目标是经验先验**：必须依靠静态基线、无课程终态、提前闭源和降低闭源等消融验证。

### 8.2 推荐的自动配比 2.0

下一版可以保持现有“六桶控制面”，增加三层反馈：数据画像层按版本自动生成分桶审计报告；采样层根据前一窗口实际 token 偏差做有界校正；实验层用多目标评分选择变体，目标同时考虑通用能力、内部域能力、训练稳定性和单位算力收益。在线校正要设置最大步长与冻结窗口，避免 sampler 与模型学习动态互相放大。

> **不要直接做无约束 loss-based sampling：** 高 loss 可能表示“更有学习价值”，也可能表示脏数据、错标或不可学习样本。自动上调前必须结合质量分、重复率、异常率和梯度影响，且设置单源上限。

## §9 项目与面试表达

### 60 秒版本

> 我把 278 个异构 CPT 数据源按来源、模态、序列成本和任务难度固化为 L0–L5 六个桶，只在 bucket 级定义五阶段 token curriculum。系统用归一化缩放公式把六维目标自动展开成 278 维权重，同时保持桶内历史相对配比不变。课程从开放短文本/图像数据预热，逐步引入视频、内部域和复杂推理，内部数据占比从 0% 增至 38%。我还设计了静态基线、无课程终态、提前引入闭源、降低闭源终态四类消融，并用长度一致、占比守恒、分桶完整、实验命名隔离等门禁保证配置可复现。

### L1：为什么不直接给 278 个数据集分别设计 schedule？

参数空间过大、难审计且难做公平消融。六桶控制把业务意图映射为少量可解释参数，再由公式保持桶内相对权重，既降低维护成本，也保留历史数据配比知识。

### L2：如何证明课程学习有效，而不是最终配比有效？

比较 `curriculum_full` 与 `no_curriculum_final_mix`。两者最终目标相同，唯一区别是前者逐步变化、后者从头固定，因此可隔离顺序和渐变带来的增益。

### L2：为什么按 token 而不是 step 划阶段？

多模态样本长度和帧数差异大，动态 batch 下每 step 的真实训练量不恒定。token 边界更接近模型实际消费的计算与信息量，也让不同 batch 配置的实验更可比。

### L3：如何处理目标占比与实际消费占比不一致？

先按 source/bucket 统计窗口级实际 token，定位长度重加权、过滤和数据可用性造成的偏差；再在不改变课程宏观趋势的前提下做有界反馈校正。任何自动校正都应保留原始目标、修正量和生效窗口，保证可回放。
